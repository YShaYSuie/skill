# md-to-word

## 定位

将 Markdown 或已有 Word 文档标准化为符合指定 Word 模板规范的 `.docx` 文档。

**核心原则：输入文档负责内容与逻辑结构；Word 模板负责视觉样式与最终编号；AI 只做必要的理解和安全结构判断，程序化逻辑稳定处理 Word 样式与生成。**

Skill 负责：输入类型识别、处理级别判断、Markdown 检查、Word 结构识别、章节编号识别、模板识别与规则分析、必要结构标准化、Word 生成、输出检查。

Skill 不负责：默认改写正文、润色业务内容、擅自重构业务章节、自定义设计 Word 样式、把普通 Word 输入强制转成 Markdown。

## 初始化与模板库

首次安装后，若不存在 `templates/default.docx`，必须向用户索要一个 Word 模板 `default.docx`。后续用户未指定模板时直接使用它，不再询问。

默认模板只能有一个，始终维护在 `templates/default.docx`。模板库模板放在 `templates/library/`，可选。

```text
md-to-word/
├── SKILL.md
├── templates/
│   ├── default.docx
│   └── library/
└── docs/template-guide.md
```

## 模板优先级

按以下顺序选择模板：

1. 本次明确指定的模板。
2. 本次上传的 Word 模板。
3. 模板库匹配模板。
4. `templates/default.docx`。

用户明确提出的格式要求，可以覆盖模板中的对应规则；用户未提出时不要覆盖模板。

模板选择规则：

- 用户没有指定模板：直接使用 `default.docx`，不询问。
- 用户明确指定模板：查找 `templates/library/<模板名>.docx`，找到后直接使用。
- 用户要求选择模板：模板库存在多套候选时通过问答确定。
- 用户描述模板类型：先匹配模板库；匹配不到时使用 `default.docx` 加用户格式要求，必要时提示 AI 补全。

本次上传的 Word 默认只用于本次任务，不自动保存到模板库。只有用户明确要求保存、继续使用、加入模板库或设为默认模板时才保存。设为默认模板前要检查 Heading 体系、正文样式、编号体系；存在严重问题要先提醒用户。

## 模板分析

使用模板前必须分析其实际 Word 结构，重点是 `Heading ↔ 编号体系`。提取：

- Heading 样式与层级
- 标题编号体系
- 多级列表
- 正文样式
- 列表样式
- 表格样式
- 图片相关规则
- 页眉、页脚
- 页面布局

不要预设编号格式。编号格式、编号层级、编号与 Heading 的关系都由当前模板决定。

模板补全优先级：当前模板已有定义 → 当前模板内部规律 → 用户明确要求 → `default.docx` → AI 合理推断。

补全规则：

- 当前模板已有定义优先，默认模板只作补充参考，不覆盖已有定义。
- 可安全推断的缺失定义自动补全。
- 存在多个合理方案时不要直接修改，询问用户。
- 编号体系冲突时不要猜测，暂停并询问。

生成过程不修改原模板。需要补全时使用模板副本。

## 输入识别与处理级别

先识别输入类型，不要要求用户学习内部参数：

| 输入 | 处理方式 |
| --- | --- |
| Markdown | 进入 Markdown 检查、标准化和模板化生成流程。 |
| Word | 判断只需样式标准化，还是需要结构标准化或模板迁移。 |
| Markdown + Word 模板 | 使用指定模板生成标准 Word。 |
| Word + Word 模板 | 保留原 Word 内容结构，按目标模板重排样式。 |

Word 输入按处理级别判断：

### Level 1：仅样式标准化

用户说“只统一格式”“不要改内容”“换成公司模板排版”时使用。优先程序化识别 Heading、正文、列表、表格、图片和特殊块，然后映射到模板样式，不生成中间 Markdown 文件，不重写全文。

### Level 2：结构标准化 + 样式标准化

用户说“结构比较乱，请重新梳理”“整理成规范报告”时使用。允许分析章节、列表、表格和标题层级，并构建内部中间结构。中间结构优先在内存中传递；只有用户明确要求保留检查稿时才写出 Markdown。

### Level 3：模板迁移

用户提供原 Word 和目标 Word 模板时使用。内容来自原 Word，样式来自目标模板。除非用户明确要求，不修改业务内容、数据、术语和章节顺序。

## 内容保护

处理已有 Word 时内容不变优先：

- 不删除段落、表格行、图片或明显业务内容。
- 不改变数字、结论、专业术语和需求含义。
- 不擅自调整章节顺序。
- 能用样式、结构映射和格式修复解决的问题，不改文字。
- 若必须做内容层面调整，在结果中逐项说明。

空段落、重复空行和明显格式残留可以清理；无法安全判断的内容保留并提示。

## Markdown 检查与标准化

生成前必须检查：

- 标题、标题层级
- 标题编号、编号连续性
- 编号与标题层级关系
- 同类编号对应的标题层级是否一致
- 正文、列表、表格、图片、引用、代码块
- 明显 Markdown 结构错误

Markdown 中的章节编号只作为结构提示，不直接作为 Word 中的普通文本。识别到结构编号时，标准化后只保留标题文字，编号信息放入中间结构的 `number_hint`。

表格和正文中的换行符号、单元格内明确的编号项也要检查：`<br>` 要转换为 Word 换行或分段；表格单元格内明确的编号项要转换为 Word 自动编号，并按单元格重新起算。

不得简单删除标题开头的数字。例如 `2026年`、`5G`、`3D`、`2.0系统升级方案` 可能是标题内容。只有能明确判断为章节编号时才移除。

同一编号模式在不同标题层级中反复出现时，必须检查层级一致性。例如模板认定 `1.`、`2.`、`3.`、`4.` 属于同一层级，而 Markdown 中却分别写成 H2、H2、H3、H2，应发现异常层级。

标准化只修改结构、格式、编号、样式映射和明显 Markdown 问题；禁止改写正文、润色语言、调整业务结论、删除内容、增加业务内容、修改数字或专业术语。需要语义级重构时先询问用户。

默认不覆盖原始 Markdown。必要时生成 `xxx.standardized.md`；输出 Word 默认为 `xxx.docx`。只有用户明确要求时才修改原始 Markdown。

## 行内格式与标点规则

生成时对段落、标题、列表项、表格单元格、引用块统一做行内解析；**代码块内容必须跳过行内解析**（命令中的 `*`、`` ` `` 等字符原样保留）。

行内标记映射：

- `**粗体**` → Word 粗体 run；`*斜体*` → 斜体；`~~删除~~` → 删除线。
- `` `代码` `` → 等宽字体（Consolas）+ 浅灰底纹 run。
- `<font color="#xxx">..</font>`（含 `style="color:#xxx"` 写法）→ 对应颜色 run；未知 HTML 标签剥离标签保留内文。
- 标记可跨行（如多行 `<font>` 块）：先做行内 token 解析，再切分换行为 `<w:br/>`，格式跨行延续。
- 未闭合的标记**原样保留**，不吞字符，并写入 warnings。

中文标点规范化（仅正文、引用、表格单元格；代码块除外）：

- 成对 ASCII 双引号在**中文语境**下转为 `“”`；单引号（≤8 字符短包裹）转为 `‘’`。
- 中文语境判定：引号包裹内容含中文，或引号外侧最近的非空白字符含中文。
- **路径/URL/命令保护**：包裹内容含盘符（`<DRIVE>:\`）、反斜杠、`//`、URL scheme、文件扩展名（.exe/.docx/.md 等）时不转换。
- 整句纯英文不转换。

## 水平分隔线

单独成行的 `---`、`***`、`___`（≥3 个同类字符）识别为 `hr` 块。**模板感知渲染**：模板定义了水平线样式（样式名 `Horizontal Line` / `HR` / `Horizontal Rule` / `水平线` / `分隔线`）时，`hr` 块引用该样式渲染；模板未定义时**跳过不渲染**，不输出任何段落。注意与表格分隔行（`| --- |`）区分：表格行以 `|` 开头，先被表格分支捕获。文档首部 YAML front matter 的 `---` 跳过不渲染。

## 表格单元格编号解析防护

表格单元格内的有序编号项（`1.`、`一、`、`（一）`）转为 Word 自动编号前，必须通过**不变式校验**：前缀之后的剩余文本（去首尾空白）必须等于正文，且正文非空。校验失败即视为误匹配（典型：IP 地址 `10.50.10.22`、版本号 `2.0`、小数 `3.14`），保留原文不拆解。编号分隔符后的负向断言（`(?!\d)`）防止点分数字被误认。

## 显式警告（禁止静默降级）

以下情况**必须**写入 warnings 并在输出中列出，不得静默处理：

- 表格单元格解析结果与原值不一致（不变式校验触发）。
- 行内标记未闭合。
- 模板缺失样式（Quote / Code / Title / List 任一）而回落 Normal 或程序化补全。
- 未知 HTML 标签被剥离。

模板缺失 Quote / Code 样式时，在**模板副本**中程序化创建（Quote：左边框+缩进+灰字；Code：Consolas+灰底），补全动作写入 warnings；不修改原模板文件。

## 实现经验（防复发，修改代码前必读）

以下条目来自真实缺陷案例，改动 `build_docx.py` 时必须遵守；每条都对应一个已修复的回归点。完整清单见 [references/implementation-lessons.md](references/implementation-lessons.md)。

## 中间文档结构

输入不直接转 Word。先构建轻量中间文档结构：

```text
Markdown / Word → Document Structure → Word
Document Structure: Heading / Paragraph / List / Table / Image / Quote / Code / HR
Heading: level + number_hint + title
```

`number_hint` 只是输入结构信息，不直接写入 Word 文本。

只有当 Word 输入必须做内容结构理解时才使用中间结构；仅样式标准化优先直接识别 Word 结构并交给程序化渲染。

## Word 生成

映射规则：

- Markdown `H1-H4` 或 Word Heading/大纲层级映射到模板中对应的 Heading 样式；模板使用中文或其他样式名时按模板实际样式映射。
- 文档开头只有一个 H1 且后续还有标题时，将该 H1 映射为不参与章节编号的 Title 样式；后续标题按模板 Heading 层级上移一级。模板没有 Title 样式时，可复用 Heading 1 并抑制章节编号。
- 章节编号映射到模板中的真实 Word 自动编号或多级列表。
- 正文映射到模板正文样式。
- 有序列表映射到模板列表样式和真实 Word 自动编号；无序列表映射到模板列表样式或模板正文的列表表现。正文编号与章节编号独立。
- 表格映射到模板表格样式；列宽按内容长度自动分配，短内容列更窄，长内容列更宽，且不超过页面内容区域。
- 表格单元格中的 `<br>` 转换为 Word 换行或分段；单元格内明确的编号项转换为 Word 自动编号，并按单元格重新起算。
- 图片按模板相关规则插入，保持比例且不超出页面内容区域。
- 页眉、页脚、页面布局尽量沿用模板。

不要向 Heading 文本手动拼接编号，也不要让正文编号错误继承章节编号。

## 执行命令约定

程序化处理时优先使用 Skill 内置脚本，不硬编码视觉样式：

- Markdown → Word：使用 `scripts/build_docx.py`。
- Word → Word：使用 `scripts/standardize_docx.py`。
- `standardize_docx.py` 默认按 Level 1 处理，可按需要指定 `structure` 或 `migrate`。
- 输出已存在时必须先获得用户确认，或明确传入覆盖参数。

## 检查与验收

生成后必须检查：

### Markdown
- 结构已检查，标题层级合理。
- 章节编号已识别，同类编号对应的标题层级一致。
- 编号与当前模板规则一致，没有误删标题中的业务数字。

### Word
- 使用正确模板。
- Heading 样式正确。
- Word 自动编号正确，没有作为普通文本重复出现。
- Heading 与编号体系正确关联，编号可以继续自动延续。
- 正文编号与章节编号独立。

### 内容
- 没有无理由删除或增加内容，没有修改业务语义。
- 表格、图片没有明显丢失。
- 非空段落数、表格数和图片数与输入基本一致；异常时提示用户确认。
- 表格中的 IP 地址、版本号、小数完整无损。
- 正文无行内标记残留（`**`、反引号、HTML 标签）。
- 中文语境引号为弯引号，路径/URL/代码保持原样。
- 水平分隔线渲染为水平线，无 `---` 文本残留。
- warnings 列出的所有降级与补全动作已在输出中说明。

### 文件
- DOCX 可以正常打开。
- 页面结构正常，样式基本符合模板，没有明显格式损坏。
- 页眉、页脚和页面布局符合模板。

## 执行流程

1. 获取 Markdown 或 Word 输入。
2. 识别输入类型与处理级别。
3. 确认本次模板。
4. 分析模板。
5. 检查 Markdown，或识别 Word 结构。
6. 识别章节编号。
7. 检查编号与标题层级一致性。
8. 检查同类编号一致性。
9. 标准化结构，必要时构建中间结构。
10. 检查模板规则。
11. 必要时补全模板。
12. 生成 DOCX。
13. 检查 DOCX。
14. 输出结果与必要确认项。

## 异常处理与输出

自动处理：明确的格式错误、标题编号问题、标题层级问题、模板缺失定义。

询问用户：多个模板无法判断、编号体系无法判断、模板规则互相冲突、修改可能影响业务语义、存在多个合理解释。

正常输出保持简洁：

```text
文档结构已检查并标准化。
已使用默认 Word 模板。
章节编号已按模板规则处理。
Word 文档已生成并完成基础检查。
```

需要用户确认时只说明真正需要决策的问题。

Word 输入的默认说明应突出：内容已保留、样式已按模板统一、编号仍由 Word 自动维护。
