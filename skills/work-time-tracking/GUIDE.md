# 工作时间与 AI 成本记录

> 自动记录你在 Codex、WorkBuddy 等工具里的工作活动和 AI 使用情况，并把结果整理成日报、周报或项目复盘。

## 你需要这个 Skill 吗？

如果你有以下情况，它可能适合你：

- 想知道今天真正完成了什么，而不只是“用了多久电脑”。
- 同时做产品工作、个人探索和日常生活，希望总结时分开看。
- 想知道 Skill、模型、Token、积分分别花在哪些项目和阶段。
- 想记录 Skill 更新了什么能力，而不想看文件名、函数名和报错细节。
- 想把工作记录同步到滴答清单，或长期保存本地日志。

## 它能帮你做什么

| 能力 | 能帮你做什么 |
|---|---|
| 自动记录 | 从 AI 会话和手动输入中提取工作事项与时间 |
| 每日总结 | 按“工作 / 探索沉淀 / 生活”三线整理 |
| 成果视角 | 产品工作按项目、阶段、交付物组织 |
| Skill 能力变化 | 区分新增能力、行为调整、能力移除和稳定性维护 |
| 过程维护折叠 | 查看日志、环境恢复、任务重跑默认不占成果主位 |
| AI 使用洞察 | 查看 Skill、模型、项目阶段和成本分布 |
| 每轮用量 | 查看每个 Turn 的 Token 总量，避免把整段会话当成一轮 |
| Skill 回执 | 按 Turn 去重展示用了哪些 Skill，并保留每次使用证据 |
| 周期复盘 | 生成日报、周报、月报和单项目总结 |
| 日报过期提示 | 日报落盘后又做了新工作，会提示“数据已过期、建议重新生成” |
| 外部同步 | 将已确认事项同步到滴答清单 |

## 什么时候使用？

### 想记录正在做的事

可以直接说：

> “记录一下，我现在在做 GPU 资源申请页面的需求梳理。”

### 想补录已经完成的工作

> “把 14:00-14:40 的产品评审会补录一下。”

### 想复盘今天

> “总结一下我今天完成了什么。”

### 想知道 Skill 更新了哪些能力

> “总结一下今天 Skill 新增或调整了哪些功能，维护和修复只简单带过。”

### 想分析 AI 成本

> “看看这周各 Skill、模型和项目阶段的 Token 分布。”

### 想同步到滴答清单

> “把今天已完成的工作同步到滴答清单。”

## 什么时候不需要使用？

- 只想管理滴答清单中的普通任务：使用 `ticktick-work-review`。
- 只想记录一条灵感：使用灵感收集类 Skill。
- 只需要一个临时便签，不希望形成长期工作日志。

## 怎么开始？

直接告诉 AI 你在做什么、什么时候做的。第一次使用时，Skill 会先确认日志保存目录，再开始记录。

## 使用前需要准备什么？

日常使用无需额外准备。第一次使用时，请准备一个希望长期保存工作日志的本地目录，并确认 AI 可以读写该目录。

## 使用后会得到什么？

- 本地工作日志与结构化记录。
- 按“工作 / 探索沉淀 / 生活”组织的每日总结。
- 项目阶段、交付物与成果视图。
- Skill 能力变化和维护活动计数。
- AI Token、积分、模型和 Skill 使用分析。
- 每个 Turn 的 Token 总量与 Skill 使用回执。
- 可选的滴答清单同步结果。

## 和其他 Skill 的关系

| Skill | 作用 | 关系 |

## 常见问题

**需要懂代码吗？**

不需要。日常使用只需要自然语言。

**“修复了什么”会出现在主总结里吗？**

纯修复和稳定性维护默认折叠，只保留计数；只有形成用户可感知能力变化时才进入主总结。

**会自动删除记录吗？**

结构化日志与总结永久保留；只有原始对话缓存默认保留 7 天。

**为什么日报上会出现“⚠ 数据截止于…”？**

说明这份日报生成之后，你又产生了新的会话，日报里不含这些新工作。
看到提示时，重新生成一次日报即可；提示只在新增会话达到一定数量（默认 3 个）时出现，
不会因为一两条零碎会话就频繁打扰。
